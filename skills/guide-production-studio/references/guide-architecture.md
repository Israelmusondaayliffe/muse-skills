# Practical Guide Architecture

Use this reference after sources and evidence are mapped.

## Start with the reader's job

Replace a topic label such as "camera movement" with the action the reader came to complete, such as "choose a camera move that supports the moment and does not fight the subject."

The job determines the explanation, example, navigation, and troubleshooting needed.

## Choose one of three shapes

### Single page

Use when one continuous read can explain the idea, show it, let the reader try it, and help them troubleshoot without becoming hard to scan.

Good for a narrow technique, quick reference, or one decision.

### Layered page

Use when beginners need a guided start and experienced readers need quick access to deeper reference material.

Suggested layers:

1. What this helps you do
2. Quick start
3. How it works
4. Complete workflow
5. Real example
6. Prompts or reusable reference
7. Troubleshooting
8. Sources beside current claims

Adapt or remove layers that do not help the task.

### Parent with child pages

Use when readers arrive with different jobs, the system has several independently reusable workflows, or a single page would force unrelated decisions into one long scroll.

The parent explains the system, vocabulary, and route. Each child page owns one reader job. A child page must not exist merely to shorten the parent.

## Component test

Every component records:

- Reader problem
- Action it enables
- Evidence that supports it
- Why it belongs here
- What breaks if removed

Remove a component when the last answer is "nothing important."

## Teaching order

Use the smallest sequence that gives the reader orientation and action:

1. Purpose
2. Plain-language concept
3. Whole workflow shape
4. First useful action
5. Real example
6. Complete workflow or reference
7. Troubleshooting and stop rules

Do not force this sequence when the reader's job needs another order.

## Prompts

A prompt earns its place when the reader needs reusable language to produce or inspect something.

Introduce it with:

- When to use it
- What to provide
- What it will return
- What it cannot know or decide
- How to judge its output

Do not use prompts to conceal missing explanation.

## Templates

A blank template comes after a completed example. Omit it if a short checklist, table, or copyable prompt is more useful.

Avoid turning every decision into a form. People need enough understanding to make the decision before they need fields for recording it.

## Downloads

Use a download when it improves reuse, printing, saving, or clean reference. The page must still contain enough value to understand and try the work.

## Parent and child boundaries

- Parent: purpose, map, shared vocabulary, where to start
- Child: one complete reader job
- Download: reusable aid
- Index: links and one-line use descriptions

Do not duplicate full instructions across these surfaces.

## Scale rule

Approve one benchmark architecture and guide before launching sibling work. The benchmark defines the quality bar, not a mandatory file structure.

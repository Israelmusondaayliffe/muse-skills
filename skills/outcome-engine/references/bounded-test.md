# Bounded Test

Use a bounded test when an important, uncertain assumption should be tested before committing to a full plan or implementation.

Define the decision, the single riskiest assumption, the cheapest reversible test, the time and authority boundary, the evidence surface, pass/fail/inconclusive rules, the stop condition, and the follow-on decision owner.

Execute only the test through `references/evidence-driven-delivery.md`. Do not quietly turn a prototype into production. At the stop condition, report the evidence and recommend: proceed, revise, abandon, or run a separately approved follow-up test.

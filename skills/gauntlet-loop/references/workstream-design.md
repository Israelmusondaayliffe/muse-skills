# Workstream Design

Create the smallest units that can improve and be judged independently without destroying coherence.

Each workstream records:

- stable identifier;
- objective or question;
- inputs and dependencies;
- allowed scope and disjoint write targets;
- expected artifacts;
- quality bar and evidence;
- builder role;
- fresh critic role;
- integration obligations;
- completion and escalation conditions;
- resource ceiling;
- handoff fields.

Read-heavy independent work is the safest parallel default. Serialize overlapping writes or use separate worktrees. One integration owner applies changes to shared files and shared decisions.

# Project Constitution

The approved `.gauntlet/plan.md` governs purpose, deliverables, scope, quality bars, evidence, authority, workstreams, integration, continuity, acceptance, and stop conditions.

## Version rules

- A proposed plan cannot authorize execution.
- Approval records the plan version, approver, timestamp, and any caveats.
- Material changes create a new proposed version.
- Execution details may change without a new plan only when purpose, scope, deliverables, authority, quality bars, resource ceilings, and acceptance stay unchanged.
- Record every material user override in `decisions.md`.

## Invalid shortcuts

- treating a task list as the constitution;
- silently widening scope;
- silently lowering the quality bar;
- treating a builder's report as evidence;
- treating resource exhaustion as success;
- proceeding past a material approval boundary.

# Routing rules

## Route selection

1. If the user needs first customers, design partners, beta users, or an early-customer report → `first-customers` (full: brief → signals → ICP → prospects → report) or `signal-research` + `icp` when they only want the hypothesis.
2. If evidence exists but the customer is undefined → `icp`.
3. If the ICP is settled but the message is not → `narrative`.
4. If the narrative is settled but channel-specific copy is needed → `outreach`.
5. If founder visibility or demand generation is the goal → `content` (LinkedIn), fed by verified claims from `narrative` or `icp`.
6. Default for "help me get customers" with no specifics → `first-customers` in standard mode.

## Sequencing

- `signal-research` → `icp` → `narrative` → `outreach` is the main chain. Each stage consumes the previous stage's validated artifact.
- `first-customers` runs the full chain internally and ends in a report; hand its ICP to `narrative` when messaging follows.
- `content` can follow any stage but may only use verified claims. Unverified claims route back to research.
- Never start `narrative`, `outreach`, or `content` on an unresolved offer/positioning decision. Write the commercial-decision gap and stop.

## Mode selection (first-customers route)

- **quick:** up to 5 prospects, light signal pass.
- **standard:** up to 10 prospects across several source types. Default.
- **deep:** up to 20 prospects plus repeated-pain pattern mapping.
- **design-partners:** prioritize testers and feedback-givers over buyers.
- **b2b:** prioritize companies, business triggers, decision roles.
- **community:** prioritize public discussion and explicit request signals.

## Action boundary

Gmail, calendar, CRM, and account actions always require a separate, explicit authorization at action time. Research and drafts never grant it. If the user asks to send, finish the draft and stop at the boundary, then report exactly what confirmation is needed.

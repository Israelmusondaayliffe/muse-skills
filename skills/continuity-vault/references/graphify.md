# Continuity Vault — graphify reference

Turn any folder of files into a persistent, queryable knowledge graph with
community detection and an honest audit trail. Outputs: interactive HTML
(`graph.html`), `GRAPH_REPORT.md`, and GraphRAG-ready `graph.json` in
`<project>/graphify-out/`.

Powered by the `graphifyy` package (external Python tool; unrelated to this
skill's authors). Muse drives the pipeline below with shell commands and its
own subagents for semantic extraction.

## Setup

```bash
pip install graphifyy            # or: uv tool install graphifyy
which graphify
```

Work in the project directory; all state lives in `graphify-out/`.

## Fast path — existing graph

If `graphify-out/graph.json` exists and the user asks a natural-language
question about the corpus (not a rebuild): skip straight to **Query**.

## Pipeline

1. **Detect.** Summarize the corpus before spending anything:
   `graphify detect <path>` (or the Python `graphify.detect` call). If 0 files:
   stop. If >2M words or >500 files: show the warning and ask the user to narrow
   to a subfolder.
2. **Extract — structural (AST).** Free and deterministic for code files.
3. **Extract — semantic.** Dispatch subagents, one chunk of 20–25 files each
   (images get their own chunk), all in parallel. Each subagent returns JSON
   with `nodes`, `edges`, `hyperedges` following these rules: node IDs are
   stable and unique, edges are never invented (use `AMBIGUOUS` when unsure),
   every node carries its source file path. Merge chunk results, deduplicating
   by node ID. Skip this step entirely for a code-only corpus (write an empty
   semantic file so the merge doesn't fail).
4. **Build, cluster, analyze.** Merge AST + semantic → build graph (directed
   only if the user asked to preserve edge direction) → community detection →
   cohesion scores, god nodes, surprising connections → `GRAPH_REPORT.md`.
   Guard: an empty extraction must not clobber an existing good graph.
5. **Label communities.** Read each community's node labels and give it a 2–5
   word plain-language name; regenerate the report with the labels.
6. **Outputs.** HTML visualization is generated by default
   (`graphify export html`). Optional: `--obsidian` (one file per node; only on
   request), `--svg`, `--graphml` (Gephi/yEd), `--neo4j` / `--falkordb` cypher
   export. Save a manifest and cumulative token-cost tracker.

Then paste into the reply (concise, not the full report): **God Nodes**,
**Surprising Connections**, **Suggested Questions**. End with one follow-up:
offer to trace the most interesting suggested question, and keep answering from
the graph as long as the user wants to explore.

## Query

```bash
graphify query "<question>"            # BFS — broad context
graphify query "<question>" --dfs      # trace a specific path
graphify query "<question>" --budget 1500   # cap answer tokens
graphify path "AuthModule" "Database"  # shortest path between concepts
graphify explain "SomeNode"            # plain-language explanation
```

Before traversal, expand the question against the graph's own vocabulary so a
wording mismatch doesn't collapse the answer. Answer only from what the graph
output contains; quote `source_location` when citing a fact.

## Incremental update and cluster-only

- `graphify --update`: re-extracts only new/changed files (code-only changes
  skip semantic extraction entirely), prunes deleted sources, re-clusters, and
  shows the graph diff. Manifests are relativized to the scan root so a later
  update after a folder move still matches cached files.
- `graphify --cluster-only`: reruns clustering on the existing graph.

## Keeping the graph fresh (host-agnostic, on Hatch)

The original plugin installed this via the host CLI. Do it directly:

- **Git post-commit hook.** In the repo's `.git/hooks/post-commit`, after each
  commit diff the changed code files, re-run AST extraction on them, and rebuild
  `graph.json` + `GRAPH_REPORT.md`. (Doc/image changes: run `--update` manually.)
- **Cron job.** For non-git folders or doc-heavy corpora, schedule a recurring
  `graphify --update` via the cron tool instead of file watching.
- **Onboarding note.** Add a short "check the graph before answering codebase
  questions" note to the project's `AGENTS.md` when the user wants it always-on.

## Honesty rules

- Never invent an edge. If unsure, use AMBIGUOUS.
- Never skip the large-corpus warning.
- Always show token cost in the report.
- Never hide cohesion scores behind symbols — show raw numbers.
- Never run HTML viz on a graph with more than 5,000 nodes without warning the user.

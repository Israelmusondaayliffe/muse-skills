# Generalized Production Doctrine

An original synthesis for this skill — generalized ideas only, not reproduced
source material. Use it as a project-owned operating guide; it grants no rights to
third-party materials and certifies nothing about current model behavior.

1. Decide before spending. A generation is evidence, not a substitute for a
   decision. Name the intended result, the non-negotiable conditions, and the
   smallest useful test before consuming a paid or limited resource.
2. Make records authoritative. The brief, asset records, performance bible,
   geography lock, shot records, and iteration records must agree. A chat
   recollection is never the source of truth.
3. Treat an asset as an identity plus an approved state. Keep distinct wardrobe,
   damage, weather, time-of-day, or prop states separate when they would otherwise
   conflict. Name them predictably and reuse the same identifier everywhere.
4. Build the world before judging the cast inside it. A location needs usable
   depth, an anchor, a light rationale, and a reverse-angle test when continuity
   matters.
5. Make performance observable. Direct a character through objective, obstacle,
   tactic, body, gaze, breath, business, and reaction. Do not ask a model to
   display a feeling without visible behavior.
6. Lock geography before style. State the camera side, landmarks, positions,
   facing directions, gaze targets, distances, and crossing rules. Re-state them
   for each independently generated shot.
7. Design one legible shot problem at a time. Keep time blocks physically
   possible, make first-frame occupancy intentional, and split a shot when its
   action cannot be controlled.
8. Preserve what works. Change one isolated variable per iteration, compare
   against the approved source, and record the diagnosis. Rebuild a broken
   premise rather than stacking repairs on top of it.
9. Separate claims from proof. A model name, prompt, or passing-looking still is
   not proof of a downstream result. Test the actual requirement, diagnose the
   earliest failed handoff, and repair there.
10. Finish as a post-production system. Edit, cleanup, color, sound, delivery,
    and learning should each preserve provenance and named acceptance conditions.
